Getting started

Get Sonara running.

Install a ready-made build in a minute, or clone the repo and run it yourself. Based on the project's README, DESKTOP.md and CONTRIBUTING.md.

EasiestInstall a releaseAndroid, Windows, macOS or Linux. No tools needed. For developersRun from sourceClone, then launch the desktop app or an Android build. OptionalWeb app & backendBrowser player, extension and the Listen Together server.

1Install a release

Every desktop download bundles its own Java runtime, FFmpeg and the Automix models — nothing else to install first.

Open the one-tap download page

  1. Pick the right APK

    Sonara-v<version>.apk is universal and works everywhere. The _arm64-v8a split is smaller and fits most phones. TV and watch have their own files: SonaraTV-… and SonaraWear-….

  2. Open it and install

    Tap the downloaded file. If Android asks, allow installs from your browser or file manager, then tap Install.

  3. Android TV or Wear OS (optional)

    TV: use Downloader, LocalSend or adb. Watch: open Settings → Wear OS in the phone app to push the bundled watch app over Wi-Fi debugging.

    TV · adb
    adb install -r SonaraTV-v*.apk
    Watch · adb
    adb -s <watch-ip>:<port> install -r SonaraWear-v*.apk

Updating from BitChord PlusPC or an older Sonara? From v1.10.0 on, releases share one signing key, so updates install in place and keep your library. Builds from before v1.10.0 and upstream BitChord used different keys — export your playlists, uninstall once, then install.

  1. Choose a package

    …windows-x64-setup.exe is the normal installer. It installs for your user, so it never asks for admin rights. The .msi is for managed deployments, and …-portable.zip runs from any folder.

  2. Run it

    Double-click the installer. For the portable build, unzip it and launch Sonara\Sonara.exe — it writes nothing outside its folder.

  3. If Automix never analyses a track

    Install the Microsoft Visual C++ 2015–2022 Redistributable (x64) and restart Sonara. It's the one component the bundled runtime can't carry.

If Windows SmartScreen warns about an unrecognised app, check the file's SHA-256 against the one GitHub shows next to it (see Verify) before you continue.

  1. Match your Mac's chip

    arm64 for Apple Silicon (M1–M4), x64 for Intel. Not sure? Apple menu → About This Mac. Requires macOS 12 or newer.

  2. Install

    .dmg (recommended): open it and drag Sonara into Applications. .pkg: run the installer. .zip: unzip and move Sonara.app to Applications.

  3. First launch

    Community builds are ad-hoc signed, not notarized. If macOS says the app is damaged or from an unidentified developer, right-click it → Open, or clear the quarantine flag:

    Terminal
    xattr -cr /Applications/Sonara.app
  1. AppImage — any distro, nothing to install
    Terminal
    chmod +x Sonara-*-linux-x86_64.AppImage
./Sonara-*-linux-x86_64.AppImage

    On Ubuntu 24.04+ it won't start without FUSE 2:

    Terminal
    sudo apt install libfuse2t64
# or skip FUSE entirely:
./Sonara-*-linux-x86_64.AppImage --appimage-extract-and-run
  2. Or use a native package
    Debian / Ubuntu
    sudo apt install ./Sonara-*-linux-amd64.deb
    Fedora / RHEL / openSUSE
    sudo dnf install ./Sonara-*-linux-x86_64.rpm

Packages are built on Ubuntu 22.04, so they run on that release and anything newer. They need a normal desktop session (GTK 3, X11 or XWayland, OpenGL, ALSA) — a minimal or headless install will fail at startup.

2Run it from source

Sonara is Kotlin Multiplatform + Compose Multiplatform, with a React web app and a Go backend. Start with the desktop app — it needs the least setup.

What to install first

ToolVersionYou need it for
GitanyCloning the repo
JDK21 (Eclipse Temurin)Desktop app and all Gradle builds
Android SDK + NDKcompileSdk 37 · minSdk 26 · CMake 3.22.1+Android phone, TV, Wear OS only. Without an SDK the build simply skips the Android modules.
Node.js + pnpmNode 22+ · pnpm via corepackWeb app and browser extension
Go1.27+Listen Together / collaboration backend

Gradle itself comes with the repo (./gradlew), and its daemon is set to a 4 GB heap, so keep some RAM free for the first build.

Steps

  1. Clone the repo
    Terminal
    git clone https://github.com/Inventor365/Sonara.git
cd Sonara
  2. Launch what you want

    Needs JDK 21 on your PATH (or selected as Gradle's JDK).

    macOS · Linux
    ./gradlew :desktopApp:run
    Windows
    gradlew.bat :desktopApp:run

    On Linux the run needs the desktop's graphics and audio libraries in the shell (GTK 3, GL, ALSA, FFmpeg). NixOS users: the repo's DESKTOP.md has a ready-made nix-shell command.

    The Android modules are only included when Gradle can find your SDK. Open the project in Android Studio (it writes local.properties for you), or create that file yourself — setting ANDROID_HOME works too:

    local.properties
    sdk.dir=/path/to/Android/Sdk
    Build debug APKs
    ./gradlew :app:assembleDevDebug :tv:assembleDebug :wearos:assembleDevDebug
    Install on a USB-debugging phone
    ./gradlew :app:installDevDebug

    Debug builds are signed with the debug key, so no keystore is needed. Release signing is covered in docs/SIGNING.md. Optional keys such as LISTEN_TOGETHER_SERVER and COLLAB_SERVER also go in local.properties and are never committed.

    Each installer must be built on the OS it's for.

    macOS
    ./gradlew :desktopApp:packageDmg
./gradlew :desktopApp:packagePkg
    Linux (needs rpm, fakeroot, binutils)
    ./gradlew :desktopApp:packageDeb
./gradlew :desktopApp:packageRpm
    Windows (needs WiX Toolset 3 on PATH)
    gradlew.bat :desktopApp:packageExe
gradlew.bat :desktopApp:packageMsi
  3. Run the tests (before you open a PR)
    Terminal
    ./gradlew :shared:jvmTest :sharedUi:jvmTest :desktopUi:jvmTest :desktopApp:test \
  :app:testDevDebugUnitTest :tv:testDevDebugUnitTest

3Web app & backend optional

The app works in Guest mode with no server. Collaborative playlists need your own backend and a Google OAuth client ID.

Web player and browser extension

Terminal
cd web
corepack enable
corepack pnpm install --frozen-lockfile
corepack pnpm --filter @bitchord/app dev          # player at http://localhost:5173
corepack pnpm --filter @bitchord/extension build  # load web/extension/.output/chrome-mv3 as an unpacked extension

Go backend (Listen Together, presence, collaborative playlists)

Terminal
cd backend
COLLAB_DATA_PATH=./data/collab.json \
COLLAB_GOOGLE_CLIENT_IDS="your-client-id.apps.googleusercontent.com" \
ALLOWED_ORIGINS="https://your-web-origin.example.com" \
PORT=8080 \
go run .

Then point the app at it in Library → Collab Account (Android and desktop) or Settings → Collaborative Playlists (web). Reverse-proxy and systemd setups are in backend/README.md.

4Verify your download

GitHub shows a SHA-256 next to every release file. Compare it with your copy's hash.

Terminal
sha256sum Sonara-*
Terminal
shasum -a 256 Sonara-*
PowerShell
Get-FileHash .\Sonara-*-windows-x64-setup.exe -Algorithm SHA256

Android releases from v1.10.0 on are all signed with one permanent certificate (SHA-256 d6d9c697…c3bb2), which is why updates install over the top. The full fingerprint is in the README.

5If something goes wrong

Android: “App not installed as package conflicts with an existing package”

An APK signed with a different key is already installed (upstream BitChord, or a local debug build). Export your playlists, uninstall the other build once, then install the release APK. Later updates install in place.

macOS: “Sonara is damaged and can't be opened”

Gatekeeper is blocking an un-notarized build. After moving the app to Applications, run xattr -cr /Applications/Sonara.app, or right-click the app and choose Open.

Linux: the AppImage won't launch on Ubuntu 24.04+

Install FUSE 2 with sudo apt install libfuse2t64, run it with --appimage-extract-and-run, or use the .deb instead.

Windows: Sonara starts but Automix never analyses anything

Install the Visual C++ 2015–2022 Redistributable (x64) from Microsoft and restart Sonara.

Collaborative sign-in says “Configure Collaboration Server URL / Google Client ID”

Open Library → Collab Account (or Settings → Collaborative Playlists on web) and enter your backend's HTTPS URL and your Google OAuth client ID.
